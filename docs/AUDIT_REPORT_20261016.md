# NautilusTrader_RL_ES 深度审计与下一阶段开发方向

日期：2026-10-16。审计对象为当前工作区，Git HEAD 为 `c24d1bc4a47584f91a4c4db93bf77117d4e8341c`，**包含大量尚未提交的变更，不等同于该提交本身**。

## 1. 核心结论

工程主链可以运行，但当前没有证据证明 RL 学到了能稳定覆盖交易成本的市场规律。最近候选的完整 Train 回放是完全空仓；控制策略几乎持续小额做空，净收益仍为负。下一阶段应从“扩大死区、降低交易损失、加速回放”转向“修复验证边界、证明信号价值、解决动作可执行性、扩大有效学习覆盖”。

本次确认了两个此前测试未覆盖的完整性问题：独立回测入口可以重复访问 Holdout 而不记账；Scaler 哈希缓存使明确设计的底层变更检测失效。此外，一次性 Holdout 限制目前只在单个运行数据库内成立。

未发现本轮检查的经济奖励重复扣除手续费的问题。收益来自原生账户权益，终端清仓计入成本；这部分设计应保留。训练奖励提高、工程校验 PASS、策略收益准入 PASS 是三个不同结论。

## 3. 当前策略到底学到了什么

### 3.1 完整 Train 账户证据

同一 seed102 的候选与控制，均回放 1,414,078 个观察、1,414,077 个动作：

| 指标 | 候选 deadband=0.10 | 控制 deadband=0.05 |
|---|---:|---:|
| 账户净收益 | 0% | -0.130560% |
| 最大回撤 | 0% | 0.674996% |
| 请求动作绝对值均值 | 0.019647 | 0.035129 |
| 请求动作绝对值 p95 | 0.044324 | 0.053781 |
| NOOP 计划 | 1,414,077 | 1,414,033 |
| 策略提交 | 0 | 44 |
| 成交记录，含终端平仓 | 0 | 45 |
| 非零执行仓位时间占比 | 0% | 99.772643% |
| 平均绝对执行敞口，风险预算单位 | 0 | 0.055093 |
| 手续费 | 0 | 1.219266 USDT |
| Funding 净额 | 0 | +12.599722 USDT |
| 滑点成本归因 | 0 | 0.247490 USDT |
| 终端空仓／清算次数 | 是／0 | 是／0 |

**单位澄清：** 动作和执行敞口分母是 `risk_budget_notional=1000`，账户初始权益为 10,000 USDT。控制平均敞口 0.055093 对应约 **55.09 USDT 名义敞口、初始账户资金的 0.55093%**，不能写成账户仓位 5.51%。权益随时间变化，精确杠杆应逐时用 notional/equity 计算。

控制报告的 `gross_return_before_reported_costs=-0.241890%` 是加回费用、滑点并剔除 Funding 后的账户归因量；正 Funding 在抵消部分亏损。它不是重新在零成本环境执行的反事实回测。因此不能把当前失败全部归因于手续费，也不能把该字段直接称作“零成本策略收益”。

### 3.2 实际训练配方及局限

| 项目 | 最近对照实际值 | 含义 |
|---|---|---|
| 算法／网络 | PPO；64×64 MLP | 单次观察输入，没有显式历史序列编码器 |
| 市场特征 | legacy，5 项 | 1m 收益、5m 波动、5m 均量、basis、最近已结算 Funding |
| 动作 | 连续 Box[-1,1]，1 维 | 目标名义敞口／固定风险预算；经软风险、硬风控、死区和数量取整 |
| steps／种子数 | 每 seed 32,768；2 seeds | 交互样本数，不是完整数据轮数 |
| episode | 8,192 步，4 窗轮转 | 每窗约 5.689 天，起点按确定性规则跨时期轮转 |
| 有效时间覆盖 | 每 seed 32,768 唯一分钟 | 约 22.756 天，只占完整 Train 决策的 **2.3173%** |
| 两 seed 的市场窗 | 相同 | 提供初始化随机性对照，没有翻倍独立市场覆盖 |
| n_steps／batch／n_epochs | 2048／512／5 | 每段收集后的优化配置；增加 epoch 不增加新行情 |
| learning_rate | 0.0001 | 固定学习率 |
| gamma／gae_lambda | 0.99／0.9 | 1m 步长下折扣半衰期约 69 分钟；GAE 权重几何尺度约 9.17 步 |
| 探索 | log_std_init=-2，ent_coef=0，动作头零初始化 | 初始标准差约 0.1353，训练随机动作与导出的确定性均值可能很不一样 |
| 奖励 | 1000×账户 log-return；本配方无额外 DD/guard 惩罚 | 缩放改善数值尺度，不改变真实收益，也不提供新预测信息 |
| 标准化 | L2 Train Scaler + 训练态 VecNormalize | 第二层随训练更新，推理时冻结；须观察各特征裁剪和分布漂移 |

839.6 天的起止跨度不等于已遍历 839.6 天。两个 seed、四个局部窗口也不足以证明跨市场状态稳定。GAE 数值是权重衰减尺度，不是“模型绝对只能记住 9 分钟”；价值函数仍参与 bootstrap。

## 4. 发现与优先级

### F1 — P1：独立 backtest 可绕过一次性 Holdout 访问记录【已复现】

位置：`packages/orchestrator/src/rles_orchestrator/application.py:1003–1030`、CLI 调度约 1157 行。

普通 `backtest` 接受 `evaluation.split="holdout"`，验证模型、窗口和预处理身份后直接回放；没有调用研究账本预留访问，也不要求已冻结配方和已登记最终训练。CLI 的输出目录不可覆盖只保护文件，换目录仍能重跑。

反例：合成行情上训练 4 步，连续调用两次 Holdout backtest 均成功、指标相同；研究数据库 `query=0、audit=2` 前后不变。**这是访问治理缺口，不代表历史真实 Holdout 已被违规重用。**

修复方向：独立回测只能产生明确标记的探索性结果；正式 Test/Holdout 必须通过共享访问服务，在读取评价行情前预留配额。重启只能复用与既有配方、模型、报告身份一致的完成收据，不能重新消费市场。

验收：普通 CLI、Python API、WFO、恢复和压力评估所有正式入口必须遵守同一授权状态；未登记不能启动正式评估。

### F2 — P1：一次性数据约束只在单个运行数据库内有效【已复现】

位置：`packages/research/src/rles_research/ledger.py:28–44,131–145`；`packages/orchestrator/src/rles_orchestrator/wfo_application.py:559,591,1043–1048`。

数据库确有唯一索引，但 WFO 将账本放在各自 `output/research.sqlite`。两个数据库能分别打开相同 Holdout SHA；同库重复则正确阻止。精确 hash 去重也不能自动识别不同快照版本或部分重叠区间。

修复方向：增加项目级数据使用登记，记录市场／数据族／时间区间／访问用途／来源版本／实验与父实验。跨运行检查时间重叠和已消费区间；运行内账本继续保留。明确什么是允许复算旧报告，什么是把旧结果重新用于选择。

验收：更换 output、protocol_id、seed 或追加其他日期的数据，均不能把已使用保留区间“变成新数据”；恢复同一完成报告不会重复计数。

### F3 — P2：Scaler 哈希缓存削弱现有冻结检测【已复现】

位置：`packages/data/src/rles_data/features.py:245–280`；`packages/gym_bridge/src/rles_gym_bridge/l2_bridge.py:65–87`；`observation.py:104–115`。

`Scaler.hash` 改为 cached_property，adapter 前后比较的都是首次缓存值。反例在缓存后用 `object.__setattr__` 模拟底层恢复／插件代码误改 mean：新计算的 digest 已变化，缓存 hash 不变，变换输出从 -2 变成 -102，仍通过前后检查。

范围：普通属性赋值依然被 frozen dataclass 阻止，本轮没有发现正常训练正在调用这种变更；这不是外部攻击或已发生数据污染的证明。但“检测 nominally frozen transformer 意外变更”的现有承诺已退化。Event、FeatureSpec、FeatureRow 的同类缓存也应统一检查，而不是把所有缓存一律视为错误。

修复方向：把绑定时的不可变统计快照与运行态 transformer 分离；对影响 transform 的 mean/std/feature_hash 做廉价结构比较，或在明确边界重新计算完整指纹。增加缓存前后变更、恢复后变更及变换内部变更反例；不要为每个分钟重复序列化全部大数据。

### F4 — P1：动作阈值掩盖策略退化，零目标也未必平仓【结果及语义已确认】

位置：`packages/gym_bridge/src/rles_gym_bridge/env.py:39`；`packages/execution/src/rles_execution/planner.py:151–159`；Stage66 报告。

候选几乎全部输出小额负值，被 0.10 死区全部抑制；控制几乎长期保持小额空头。Stage63 的训练 reward 配对改善并不能证明策略更会预测。减少随机探索期间的成本、导出均值后不交易，都可以造成这种表象。

另一个已复现语义：风险预算 1000、当前名义敞口 50、有效平仓量高于交易最小值时，普通目标 0 在 deadband=0.10 下仍是 `NOOP/deadband`。强制风控和平仓终态绕过死区，但策略主动回到零仓位没有单独语义。这与“目标零就是平仓”的直觉不一致，必须在策略契约中写清。

修复方向：保留原动作作为对照，比较显式 hold／flat／rebalance 的可执行映射、离散目标仓位，或有明确退出通道的连续目标。离散方案需要同步修改 provider 的动作契约，不能直接把 Box 改成 Discrete 后继续沿用所有算法。不能通过奖励交易次数强迫无信号交易。

验收：对请求、软风险后、硬风控后、数量取整后、真实成交后五层分别统计；确定性策略必须与同风险空仓、固定多空和简单因果规则比较。是否换向或持仓时长不是单独的盈利门槛，但长期恒定仓位应归为方向基准，不能称为学到了择时。

### F5 — P1：学习覆盖和时间尺度仍不匹配【配方事实，非单一亏损因果证明】

位置：Stage62/63 配方及覆盖摘要；`historical.py:153–180,371–408`；`rl_stage.py:84–112`。

轮转取样已解决“永远只从首窗开始”，但最近有效覆盖仍只有 2.32%。训练 5 个 epoch 是重用当前 rollout，并不等于重学完整历史。gamma=0.99 的分钟折扣偏向短期，而探索开平仓成本立即发生；与希望捕捉更慢波动的目标存在待验证的尺度问题。

建议将“1m 引擎推进”和“策略多久决策一次”分开实验，维持中间资金费／风险／权益更新。用目标折扣半衰期反推 gamma，而不是仅堆 n_steps。增加分层市场窗覆盖，报告唯一时间覆盖、各月／趋势／波动状态样本和真正的重复次数。

验收：预算扩大前先在训练内部诊断池看到学习曲线及基准优势；按固定预算阶梯观察 100k→300k→足够覆盖全 Train 的交互量，不能仅因跑满预算就升级。预先定义失败停止条件，避免无限微调同四个窗口。

### F6 — P2：强制平仓终点与 SB3 bootstrap 的目标需统一【源码路径已确认，收益影响未实测】

位置：`episode.py:314–315`；`env.py:189–205`；`rles_rl_sb3/envs.py:164–165`。

正常历史窗结束被标为 truncated，环境随后实际清仓并计入清仓成本。SB3 2.9.0 的本地 `on_policy_algorithm.py:236–245` 会对 TimeLimit.truncated 的 terminal_observation 加 gamma×V 进行 bootstrap。当前因此既支付终端清仓成本，又估计已清仓状态之后的延续价值。

如果目标是有限期、结算结束的 episode，应终止价值；如果目标是持续交易任务中的采样切片，应定义是否跨切片延续仓位及对应后继状态。当前混合语义至少需要明确设计和单步可计算反例。**不能在未做对照前宣称它造成了当前亏损。**

验收：固定可解析价值函数，核对终点 reward、价值 target、终态观察和费用；单环境、并行环境、恢复路径一致。

### F7 — P2：长持仓回放仍反复序列化历史，compact 也不是流式指标【源码确认，需补增长曲线】

位置：`packages/nautilus_adapter/src/rles_nautilus_adapter/session.py:112–125,169–170`；`historical.py:425–481`；`native_metrics.py:74–84`。

打开仓位时先执行完整 `Position.to_dict()`，再丢弃 events/adjustments 等历史字段；funding 每次从累计 adjustments 枚举并去重。未平仓长持仓上的历史增长仍会增加每步开销。下游 compact 能降低保留内存，但不能省掉前面的构建成本。

`include_account_rows=False` 仅不把 rows 放进最终报告，`native_report` 仍完整构建 rows，指标还会复制数据；factory 也保留所有分钟快照。当前可跑通，不等于常数内存流式实现。

已有控制全 Train 约 2.5 小时，而空仓约 18 分钟；两者轨迹不同，该差异只支持进一步 profiling，不能把全部耗时归给某一函数。Stage67 的 8192 步汇总指标、动作分布、计划数量一致，耗时约 10.239→7.152 秒；**并未比较逐步动作轨迹，不能声称已经证明完整轨迹一致**。短回放包含 reset/import，不能外推整个百万步运行的加速比例。

建议：优先持久增量 funding/fill 账本和轻量当前仓位读取，再做共享只读行情／特征数组；补 1d/30d/长窗的空仓、长期持仓、多次调仓基准。均值方差／权益累计可流式，分位数、bootstrap 等明确各自存储成本。保留完整事件可追溯性。

### F8 — P1 验收阻塞：真实行情不等于真实历史交易经济模型【已知限制仍存在】

最近配方使用 bar-conservative-1bp 与 5bp 压力场景、假定延迟及规则文件。旧审计指出的完整历史费率、交易约束及保证金有效期证据尚不能由这些场景参数替代。`HISTORICAL_RULES_BLOCKER.md` 的行情覆盖描述也早于当前扩展数据，应更新。

这不阻止做明示假设的 RL 研究，但即使样本外为正，也先只能表述为“在指定成交／费用场景下通过”。本次没有重新联网核验交易所规则，故不新增当前规则或历史真实性结论。

验收：模型、行情、规则有效期、费用、延迟和成交场景一并冻结；缺失的事实显式列出。成本压力通过不等于历史规则已补齐。

### F9 — P2：实验复现资料过度依赖被忽略的 .tmp【已确认】

Stage62–68 配方、验证器、模型和大多数证据在 `.tmp`，Git 默认忽略；本轮前的性能临时脚本已经删除，只留下 JSON 结果。文档写了 hash 不能替代可下载数据、模型和可执行复现实验。HEAD 也不能定位大量未提交修改。

建议：将配方、验证器、数据取得方式、源码身份及小型验收摘要纳入版本管理；大工件存入有校验清单的持久目录或发布工件。公开源码仓库可供外部读和 clone，写入权限保持维护者限定；公共读取不意味着别人不能修改自己的 fork。发布前完成一次干净 checkout 复现，不把本机 `.tmp` 状态当作前提。

| perf 标记没有测试 | 已修复，目前 1 项；长期训练性能仍缺验收 |
| 可复现的盈利与多折稳定性 | 仍未达成；近期零收益为空仓，负收益控制仍无优势证据 |

## 6. 下一阶段开发顺序与完成标准

### 阶段 A：先恢复可信验证边界

修复 F1/F2，恢复 F3 的冻结检测；明确 F6 的终端价值语义并补反例。整理现有已消费时间段，禁止把历史已看过的 Holdout 重新包装成新保留集。

完成标准：所有正式评价入口统一记账；跨目录重复／重叠访问被识别；冻结统计量变化被阻止或检出；终点 target 在数值上可解释；全量 CPU 测试通过。

### 阶段 B：建立“信号是否存在”的低成本基准

在已允许研究的 Train 内预先划分开发窗和内部诊断窗，按时间滚动，设置与特征／预测周期匹配的隔离间隔。内部诊断窗参与研究后也属于开发数据，不能冒称最终独立 OOS。

同一成本、仓位预算和数据上比较：空仓、固定多空、简单趋势／反转、低容量预测模型、当前 RL。预测任务可比较 5m/15m/60m 的未来净价格变化；未来值只作训练标签，不能进入策略观察。先检查分组收益与成本门槛，再决定是否增加复杂网络。

完成标准：能解释 RL 的收益来自择时、长期方向敞口还是 Funding；至少在多个内部时间窗表现出可重复的基准优势，否则先改善数据／特征／决策周期。

### 阶段 C：动作、奖励、周期的有限配对实验

建议预登记最多 8–12 个配方，避免一次穷举所有组合：

| 维度 | 第一批值得比较的方向 | 必须同时观察 |
|---|---|---|
| 动作 | 当前目标仓位对照；显式退出的连续目标；少量离散目标档位 | 有效动作覆盖、主动平仓、换手、恒仓退化、成交成本 |
| 决策周期 | 1m 对照；5m／15m 决策，底层仍逐分钟推进 | 持仓收益、资金费、风险事件，不跳过中间账户变化 |
| 奖励 | 纯净权益 log-return 固定缩放；轻量回撤 shaping 配对 | 原始 r_econ、shaping、critic loss、优势尺度、账户净值 |
| 时间信用分配 | 按 1h／6h 等预定半衰期设置 gamma，再比较 GAE | 长短收益权重、方差、终点 target；参数值不代表必然改善 |
| 学习率／更新次数 | 现有 1e-4、5 epochs 作锚点，小范围配对 | KL、clip_fraction、entropy、value loss、explained_variance、冻结策略曲线 |
| 特征／时间窗 | legacy 对照；MTF；价量状态；可靠资金费日程 | 增量消融、裁剪比例、漂移、未来可见性反例 |

不对交易次数本身发奖励，不删除真实交易费用，不以训练 loss 或交易活跃度作为盈利替代物。奖励缩放变化时重新检查 critic/entropy 等相对尺度，不能假定乘常数对整个 PPO 更新完全中性。

完成标准：先用同窗同种子的配对实验排除完全空仓、无优势的固定方向和高换手亏损；筛选用至少 3 个 seed，晋级后建议 5 个以上。报告 seed 离散程度和窗口差异，不能只发布最好一次。

### 阶段 D：扩大有效训练与按吞吐分配资源

仅对通过机制筛查的少量候选扩大覆盖和训练预算。将 100k、300k 及更长阶段作为事先定义的观测点，独立记录实际唯一行情覆盖、重复次数、训练／冻结推理差异和耗时。

先测 1/2/4 worker 的有效样本/秒、序列化时间、系统 commit、可用内存及磁盘增长，再确定并行度。优先共享只读数据和增量原生事实；CPU 原生回放占主导时，盲目加 learner GPU 或线程可能没有收益。

按用户要求，约 1 GiB 可用物理内存作为最终底线；在预计下一个 worker／episode 启动会突破底线前停止扩容、保存进度。这个底线不能当作日常满载目标，因为启动临时峰值和系统 commit 仍可能不足。不杀其他非本任务进程。

完成标准：在同样经济结果及状态轨迹下吞吐确有提高；持续运行资源不随持仓历史失控；强杀／内存压力后能恢复到有校验的完成检查点。

### 阶段 E：冻结配方，做真正独立的验收

训练内部选完配方后，一次性冻结代码、数据、特征、动作、奖励、种子集合、选择标准、费用及执行场景。先进行多折顺序验证，再对未参与任何筛选的未来或保留时间段做最终验证；已消费保留集不再调参。

预先约定净收益、最大回撤、压力成本、风险事件、跨 seed／窗口稳定性及与基准比较的通过标准。对自相关收益使用合适的区块重采样，不把分钟 Sharpe 单值当作显著性证明。验证不通过就记录失败，并为新一轮获取新的独立验证机会。

完成标准：另一进程从保存工件重现；干净环境能够复现；多个时间窗及 seed 支持净收益优势；最终未消费数据通过预定门槛。即使如此，也只能说明通过了该验证协议，不能保证未来持续盈利。

### 阶段 F：可交付与源码备份

发布可审查的源码版本、实验清单、复现命令和小型结果摘要，单独管理大数据与模型工件。公共 GitHub 仓库的外部读／clone 与写权限分别配置。本次为审计交付，没有把现有未提交开发修改混入一次发布，也没有宣称已完成 GitHub 备份。
