# RL 训练设备速度对比（2026-10-16）

## 结论

本次实测中，**CPU 单环境最快**：完成相同的 32,768 个 PPO 交互步用时 77.2 秒，吞吐 424.4 步/秒。CUDA 单环境用时 113.2 秒，慢约 46.7%；CUDA 学习器配两个 CPU 环境用时 246.9 秒，慢约 3.20 倍。

| 配置 | learner | Nautilus 环境采样 | 交互步 | 耗时 | 吞吐 | 相对 CPU |
|---|---|---:|---:|---:|---:|---:|
| CPU | CPU | 1 个环境 | 32,768 | 77.2 秒 | 424.4 步/秒 | 1.00× |
| CUDA 单环境 | CUDA | 1 个环境（CPU 仿真） | 32,768 | 113.2 秒 | 289.4 步/秒 | 0.68× |
| 混合双环境 | CUDA | 2 个 CPU worker 环境 | 32,768 | 246.9 秒 | 132.7 步/秒 | 0.31× |

建议当前这套 64×64 PPO MLP 训练先用 `rl_device=cpu`、`rl_num_envs=1`。本次 CUDA 训练期间 GPU 利用率抽样约 1–7%，显存占用约 1.3 GiB；SB3 也发出了 PPO MLP 更适合 CPU、GPU 利用率可能很低且训练更慢的提示。Nautilus 历史仿真本身始终运行在 CPU。

## 可复现配方

基于 `.tmp/rl-stage66-memory-bounded-full-train-replays-20261016/control-seed-102-config.json`，数据和规则来自该冻结配置。三组共用同一个预先构建的训练工厂，并且都关闭独立评估，避免把重复市场数据准备和评估工作混入设备训练计时。

- 路由 A0、PPO、seed 102、总交互预算 32,768 步。
- 网络 64×64，观测归一化，奖励缩放 1000。
- `n_steps=2048`、`batch_size=512`、`n_epochs=5`、学习率 `1e-4`、`gamma=0.99`、`gae_lambda=0.9`，其余 PPO 参数完全沿用冻结配置。
- 每个 episode 8,192 步；固定观测语料为 1×256 步。
- 三组使用相同市场快照；单环境两组的设备、环境数、训练配方相同，仅 learner 设备变化。
- 训练入口计时包含 learner/环境启动、训练、保存与产物整理，不包含共享训练工厂约 190.2 秒的首次准备时间。

项目当前没有独立的混合设备选项：`cpu` 与 `cuda` 描述 learner 设备，Nautilus 仿真使用 CPU。本次“混合双环境”是 CUDA learner 加两个 CPU 采样 worker 的实际组合，唯一额外变化是 `rl_num_envs=2`。总交互步仍保持 32,768，但 SB3 的每轮 rollout 从 2,048 变成 4,096 步，因此更新次数随之变化；该组反映现有 worker 启动/数据重建成本下的端到端实际速度，不是只改变硬件而保持算法更新轨迹不变的严格对照。

这些时间是每组一次的机器实测，适合当前设备选择，不构成多次重复的统计基准。速度测试不包含验证集评估，不能据此判断策略收益或 CUDA 模型是否产生更好的策略。

## 优化方向

1. 此规模的 MLP 保持 CPU learner 和单环境作为速度基线；将 CUDA 留给更大网络或批次，再单独测量学习器更新耗时和端到端收益。
2. 混合组变慢的关键成本来自 Windows subprocess worker 各自重建历史环境工厂。下一阶段优先让只读市场数据和特征在 worker 间共享或高效映射，并缩短 worker 冷启动；之后再调 `rl_num_envs`。
3. 并行环境会改变每轮 rollout 与 PPO 更新次数。后续比较学习效果时，应同步控制总环境步数、优化器更新预算和市场时间覆盖，再对冻结验证区间作独立评估。
