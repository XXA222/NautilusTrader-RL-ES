## 1. 架构与责任

### 当前集成补充（2026-10-13）

- `windows_job.py` 提供 `WindowsWorkerJob(memory_bytes)`，按单 worker 和其整个后代进程树限制 **committed memory（提交内存）**，不是 RSS。协调器持有唯一非继承 Job handle，关闭最后 handle 时终止树。限制在 assign 成功后生效；Python spawn 引导阶段不作追溯限制，生产工厂在 assign 前由启动门阻塞。
- `CPUWorkerPool(..., enforce_memory_limit=False)` 保留底层旧接口的配额模式；显式开启但平台不支持时启动前拒绝。`resource_evidence()` 返回实际 Job 上限、峰值、活动/累计进程数；关闭必须确认整树无活动进程才释放配额。无法确认时保留租约。
- 应用级 Windows ES 默认开启硬限制，`worker_ram_bytes` 默认 2 GiB、必须为正整数且不超过当前 4 GiB run quota；`enforce_worker_memory_limit` 必须为 Boolean。非 Windows 默认 `quota_only`，显式请求 Windows 硬限制则拒绝。WFO 在数据读取、协议建立及查询记账前执行同一策略校验；资源策略来自根配置并贯通所有候选和重训。
- 新 `run.json.worker_resources` 冻结配置并在恢复时核对；bundle 的 `runtime_resources` 说明作用范围。每次 E1/E2 执行写独立 `*-resources-<uuid>.json`，避免恢复覆盖既有证据；这些易变统计不进入 actor 身份。
- **范围仍有限**：协调器、R1 learner、VRAM 和整机 CPU 未由此约束；父进程硬退出虽能关闭其 Job 树，不会自动回收 SQLite 租约或 GPU 文件锁。未知 owner 仍须显式核实后恢复。
- 实际证据及命令见 `docs/DEVELOPMENT_GOAL_CURRENT.md` 的“Windows worker 内存硬限制与原生强杀”节。该功能只部分关闭 F11，完整设计验收未通过。

- **L6 Compute**：CPU Engine 的 spawn 调度，配额及独占 GPU Lease，同步 RL vector barrier，异步 ES candidate 评价，端到端性能决策及容错；不修改算法采样预算、不创建交易账本、不实现 RL/ES 的优化数学。
- **L6 Research**：ArtifactStore、研究查询账本、WFO 请求及 L2 FoldManifest 校验、非学习基准动作、原生账户流水指标、bootstrap/DSR/CSCV-PBO、约束优先候选、冻结 recipe 和 Final Holdout 一次开启。交易事实及 HardRisk/Execution 均由其他授权线提供。
- **L6 QA / Upgrade / Release**：质量门禁和证据校验、双 Adapter 差异审查、依赖版本回归记录、回滚计划、安全扫描、发布清单和 Q6–Q9 证据索引。L6 不实施最终 release/tag/merge，也不产生集成报告或工件作为本模块交付物。
- **依赖倒置**：中立 DTO/Protocol 的所有权在 **L1 rles-contracts**，FoldManifest 的所有权在 **L2 rles-data**，引擎/环境提供者在 **L3**，算法在 **L4/L5**。本线实现不复制、不改动这些外部模块。

## 3. Compute 公开接口

### 3.1 设备解析和冻结（L6C-001/008/009）

- `DeviceResolver.resolve(requested, *, decision=None, current_fingerprints=None, benchmark_report=None) -> ResolvedDevice`
- `benchmark(modes, run_once, *, frozen_fingerprints, repetitions=3) -> dict`; `validate_benchmark_report(report) -> sha256`；`worker_scaling_benchmark(run_once, frozen_fingerprints, workers=(1,2,4), repetitions=3, max_peak_rss_bytes=...)`
- `device_decision(report, *, max_p95_latency_ms, max_numeric_error, min_speedup_fraction=0.01, reviewer_approved=False) -> dict`

`requested` 必须是 `cpu|gpu|hybrid|auto`。`auto` 强制附原始 Benchmark 报告并重新核验样本预算、摘要、SHA256、指纹及批准过的决策；每一个 Resolver 实例只允许尝试解析一次，失败也不得在同一个实例内从 GPU 切回 CPU。`gpu/hybrid` 的 learner 为 CUDA，而所有 Nautilus Engine 必须在 CPU。GPU unavailable 必须失败，不自动退回 CPU。Benchmark 至少三次，CPU/GPU 的 environment steps、ES evaluations、model params 必须一致；结果包括 median end-to-end wall time、p95 action latency、peak RSS/VRAM、PCIe 字节和数值偏差。

**冻结指纹集合**：`dataset_sha256`, `seed_tree_sha256`, `actor_signature_sha256`, `execution_sha256`, `risk_sha256`, `algorithm_config_sha256`；全部是小写 SHA256。`run_once` 是由集成方注入的真实完整训练/评估探针，不能用 GPU utilization 或单纯 kernel timing 代替。

### 3.2 资源约束（L6C-002/004）

- `ResourceQuota(db_path, cpu_cores, ram_bytes, gpus=1)`；`acquire(owner, *, cpu_cores, ram_bytes, gpus=0) -> Lease`；`release(lease)`；`active()`。
- `GPULearnerLease(directory, gpu_index)`；`acquire(attempt_id) -> token`；`release()`。
- `ComputeAllocation(quota, owner, attempt_id, cpu_cores, ram_bytes, learner_device, gpu_lock_directory, gpu_index=0)`；`acquire()/release()`：先预留总 CPU/RAM/GPU 配额、再夺取指定 GPU 排他所有权，冲突则回滚配额；GPU 锁释放异常时保留配额阻断第二个 learner。

配额通过 SQLite `BEGIN IMMEDIATE` 跨进程占用。CPUWorkerPool 启动前**强制取得 CPU 和 RAM 额度**。每 GPU 文件排他锁拒绝第二位 learner owner。无法确认全部 Worker/后代终止时保留 ResourceQuota 租约，阻断资源超卖；异常进程的租约不能按模糊 PID 推测自动解除；必须显式确认没有残余 Engine/CUDA 上下文后再恢复。ResourceQuota 本身是**资源预留账本**；当前 Windows 应用额外启用上述 ES worker 提交内存硬限制，其他平台和协调器/learner 仍需相应 OS 约束。

### 3.3 Worker / RL / ES（L6C-003/005/006/007）

- `CPUWorkerPool(workers, factory_ref, factory_config, mode, quota, lease_owner, ram_bytes_per_worker, cpu_cores_per_worker=1, startup_timeout_s=30, torch_threads=1, enforce_memory_limit=False)`；`start()`, `dispatch(jobs, timeout_s)`, `dispatch_candidates(candidates, timeout_s)`, `resource_evidence()`, `close()`。
- `RLTrainLane(pool, timeout_s).barrier(keys, actions, operation='reset'|'step')`。
- `ESEvalLane(pool, timeout_s).evaluate(candidates) -> {candidate_id: result}`。

IPC 消息必须携带 `run_id`, `attempt_id`, `env_id`, `episode_id`, `step_id`, `candidate_id`, `model_id`, `schema_version`, `dtype`, `shape`；所有响应需要完整键一致，数据只可为小 JSON DTO（每消息不超过 1 MiB），不能 pickle 大型 DataFrame、真实 Engine 或整折行情。Queue 容量为每 worker 1 个任务；池仅使用 `multiprocessing.spawn`。每个调度池拒绝同时派发两个请求；`close()` 与派发互斥。RL Worker 的 READY 要求真实 L3 Engine 初始化成功；CPU Worker 禁用 CUDA 可见性。`factory_ref` 是**可信已安装模块**的 `module:public_callable`，由 L3 Provider 负责构造 session。RL 每个 worker 保留独立 session，所有环境本步完整返回后才返回整个 batch；异常/超时关闭整池。ES 每候选新建/关闭 session，最快完成的 worker 立即领取下一候选，结果按 `candidate_id` 匹配。所有模型训练算法、SB3 原生 `VecEnv` 数据表示和 episode 终止后自动 reset 的真正语义，仍由上游 L3/L4 提供，不由本调度器伪造。

### 3.4 故障（L6C-010）

- `decide_fault(fault, fallback_policy, reviewer_approved=False) -> FaultDecision`。
- `FaultInjector(research_sandbox=True, reviewer_approved=True)`，仅可在受控无交易凭据的研究沙箱注入 worker 异常或合成 CUDA 错误边界。

默认 `fail_fast`。`approved_cpu_retry` 仅可在 **CUDA 故障、明确人工审批后**选择 `NEW_CPU_ATTEMPT`；不会静默改变当前设备，使用方必须重新分配 attempt_id 并附可比性警告。合成 CUDA 边界**不等同于真实 CUDA OOM 压力试验**。

## 4. Research 公开接口

### 4.1 ArtifactStore（L6R-001/002）

- `ArtifactStore(root, trusted_sources)`；`begin(run_id,attempt_id) -> ArtifactWriter`。
- `ArtifactWriter.add(name,content_bytes)`；`complete(l1_manifest,required_files,trusted_source_id) -> Path`；`fail(reason_code)`。
- `ArtifactStore.verify(run_id,attempt_id,expected_manifest_hash=None)`；`read_bytes(run_id,attempt_id,name,expected_manifest_hash,allow_serialized_model=False)`。

完成过程：先写到 `.staging` → 文件与 L1 指纹验证 → 同文件系统 `rename` 至 `attempts/<id>` → 最后 `COMPLETED`。仅 `COMPLETED` 可见。拒绝未知来源、缺少强制文件、hash 不匹配、缺失 manifest、被篡改内容。允许存储二进制模型**字节**，但本模块**不反序列化** `.zip/.npz/.bin`，下游需要独立信任审核。`trusted_sources` 是 operator allowlist，**不等同于密码学签名**；外部模型加载方必须再核查版本锁、签名和安全格式。

**L1 manifest 必备 SHA256**：`data_hash`, `code_hash`, `config_hash`, `seed_hash`, `deps_hash`, `adapter_hash`, `compute_hash`, `execution_hash`, `risk_hash`。完整缓存身份另需绑定 feature/actor/engine/device-numeric-profile，须经 ICR 与 L1 对齐后才能宣称跨设备 cache/reuse PASS。

### 4.2 SelectionLedger / Holdout（L6R-003/010/011）

- `ResearchLedger(database)`：`create(protocol_id,run_id,validation_budget,hpo_budget,es_evaluation_budget)`, `record_query(protocol_id,query_id,kind,candidate,fold_id)`, `reserve_es_lane_requests(protocol_id,spec,stage,requests)`, `verify_es_lane_reservations(protocol_id,run_id,attempt_id,stage,request_keys)`, `query_counts`, `freeze_recipe(recipe_sha,code_sha,selection_spec_sha)`, `register_retrain(retrain_sha,pre_holdout_end_ns)`, `open_holdout(holdout_dataset_sha,reviewer_approval_sha,holdout_start_ns)`, `close_holdout(report_sha,conclusion)`, `evidence_summary(protocol_id)`。
- `SelectionLedger(ledger,protocol_id)`：`receipt_hash_for(spec,stage,artifact_id,payload_hash,usage)` 供不可变 L5 `StageArtifact` 预先嵌入收据；随后将 `SelectionLedger` 作为 L5 `Orchestrator(attest_usage=...)` 的回调，事务性持久化 E1/R1/E2 的阶段、运行/尝试、制品、预算、用量与 receipt hash，并追加至 SQLite 审计链。当前用量收据路径有跨 L5/L6 持久化测试。
- `SelectionSpec(max_drawdown,max_turnover,max_risk_violations,primary_metric,maximize=True)`；`choose(spec,candidates,fold_stage='validation')`。

Ledger 记录 validation、HPO、ES 种群评价、fold Test 查询，并在并发事务内执行创建研究协议时冻结的三类查询预算（Validation >0，纯 RL/纯 ES 消融场景允许未使用的 HPO/ES 预算为 0）。ES lane 必须通过 `reserve_es_lane_requests` 在 worker 派发前逐请求持久预扣；失败进程、部分执行和新 attempt 不会返还预算。该费用与 `record_query(kind='es_evaluation')` 共用 `es_evaluation_budget`，同一派发不可再重复登记为查询。checkpoint 恢复前 `verify_es_lane_reservations` 要求账本请求 key 集合与 checkpoint 完全一致；阶段 receipt 会再次复核成功阶段用量与该 attempt 的持久预留数量相等。`evidence_summary` 保留每条请求、attempt 和 stage 供审计。状态为 `DEVELOPMENT → RECIPE_FROZEN → RETRAINED → HOLDOUT_OPENED → CLOSED`；冻结后不得追加 validation/HPO/ES 选择查询，Test 同折只能执行一次。Holdout 一经 `open_holdout` 原子提交，同一数据集 SHA 在此 Ledger 中不能被不同 protocol 再次打开，不得重开，即便最终结论 `FAIL`。`reviewer_approval_sha` 是外部签核证据指纹，而非凭空授信。SQLite 审计链用于发现普通修改，不是对拥有数据库写权限的对手提供的独立防篡改服务。

`StageUsage.from_rl_performances` 从 L4 `Performance.samples` 汇总实际 SB3 timestep delta，支持把同一 R1 阶段的中断前后所有 train calls 一并计入；`StageUsage.from_evolution_result` 从 L5 `EvolutionResult` 读取真实 generation/evaluation 计数并绑定冻结 population size。ES 的 `evaluations` 是 candidate objective 次数；`lane_requests` 是 L6 ESEvalLane 实际处理的 candidate×episode 请求次数，两者有独立的 `max_evaluations` 与冻结 `max_lane_requests` 上限，并共同进入 SelectionLedger receipt。L4 原生 Env 训练、恢复续训和 EvoTorch 原生 episode 测试已验证这些 adapters 对应实际 Provider 返回值。`GenerationLaneEvaluator` 将每代 candidate×episode worker evidence 纳入可恢复 checkpoint 和 evidence hash；集成路径通过实际 `EvaluationBudget.consumed` 写入用量。该收据不实现 ICR-L6-008 的有效独立 trial 数/DSR 计费审批，也不证明完整生产 E1→R1→E2 管线已装配。

### 4.3 WFO / Baselines（L6R-004/005）

- `plan_folds(start,end,scheme,warmup,purge,embargo,step_days=15,final_holdout_start=None,data_available_from=...) -> list[FoldRequest]`。
- `validate_l2_manifest(request, manifest_mapping)`。
- `BaselinePolicy(BaselineSpec(name,seed,target_long=1,momentum_lookback=20)).action(closes)`。

WFO 只输出折请求，**不实现和不覆盖 L2 的 FoldManifest**。只支持 `60/15/15`、`360/15/15`，Test step=15 天，UTC 时间，显式的 warmup/purge/embargo 与 `force_flatten_with_cost`；可用数据必须覆盖 warmup，Test 绝不可越过最终 Holdout。B0–B3 只输出原始 exposure，必须经 L3 Engine、ExecutionPlan 和 HardRisk，与学习算法使用同一账户成本语义；B2 仅用历史已闭合 closes，B3 由固定 seed 驱动。

### 4.4 经济指标与统计（L6R-006/007/008/009）

- `from_account_facts(facts,periods_per_year,realized_trade_pnls=None,sample_interval_ns=...)`；`series_metrics(returns,periods_per_year,...)`。
- `block_bootstrap(returns,block_length,draws,seed,confidence,statistic)`。
- `deflated_sharpe(returns,effective_trials,trial_sharpes,risk_free_per_period=0)`。
- `candidate_set_sha256(candidate_ids)`；`pbo_cscv(candidate_returns,candidate_ids=...,max_partitions=10000,candidate_set_hash=...)`。

AccountFacts 最低包含递增 `ts_ns`、正 `equity`、`external_cashflow`、`turnover_notional`、`fee`、`funding`、`slippage_cost`；采样间隔必须一致。计算现金流调整的几何净收益、最大回撤、Sharpe/Sortino、turnover、费用/资金费/滑点构成和尾部 VaR/CVaR。Trade PF 只在拥有来自引擎的真实**已平仓交易** PnL 列表时计算，不能把权益正负分钟误称 trade PF。没有定义的 Sharpe/Sortino/PF 返回 `null/None` 而不是虚构值。所有经济指标不以 shaped reward 为输入。

采样行中的 `external_cashflow`、`turnover_notional`、`fee`、`funding`、`slippage_cost` 均为该采样区间的增量，不是累计总额；外部现金流按采样边界计入，区间中途发生现金流时必须在该时刻拆分采样。Funding 保持原生现金流符号（收入为正、支付为负），fee/slippage 为非负成本。L6 仅从权益生成净回报，gross-before-reported-costs 汇总成本时每项只还原一次。

训练 rollout 的回测报告另含 `action_diagnostics`，分别汇总策略原始 `requested_action` 和风险链完成后、终端强制平仓前的 `policy_executed_action_pre_terminal`：动作均值/绝对值均值/P95、非零参与率、两者差值均值/P95及被改写比例。`abs(action)>1e-6` 定义为非零/已改写；这些暴露诊断不替代账户成交、风险干预及经济指标，也不进入候选 Selection 的净收益计算。

Bootstrap 明确 block_length/draws/seed；DSR 必须传入追溯到 SelectionLedger 的有效 trial 数、trial Sharpe 分布，并记录 skew/kurtosis；CSCV/PBO 需要冻结候选 ID 列表并验证其 SHA256、相同时间切片样本数量、限制组合数量，常数收益与不具辨识力的样本拒绝计算。该统计实现是研究方法组件，**不能替代统计审计或误差条专家复核**。

## 5. QA / Upgrade / Release 接口

- `GateRunner(trusted_producers).evaluate(gate,evidence,checks,reviewer_approved=False)`；`verify_gate_reports(reports,trusted_producers)`；`load_gate_reports(directory,trusted_producers)`：固定 Q0–Q10 检查目录、前置 Gate、逐检查项独立证据 ID、哈希核验和审批。发布阶段会重新计算所有报告的摘要、复验原始证据文件及冻结前置 Gate，禁止仅凭 PASS 字段放行。`research_release_ready()` 只要求 Q0–Q9；Q10 另属 Paper Trading。报告默认为 BLOCKED，未知检查集不接受。
- `ci_plan(layer)`：`pr/nightly/gpu/release` 分层，GPU 需受控自托管 CI。可复用 workflow 的集成测试目录由总集成方提供，AI-06 不打包测试。
- `compare_adapter_traces(old,new,numeric_tolerances,expected_fix_paths,reviewer_approved_paths)`：A 预期修复、B 有限容差、C 破坏；**任何 A/B 差异未被明确审批仍为 BLOCKED；任何 C 必须回滚**。
- `dependency_regression(versions,checks,evidence_hashes)`：Python/torch/SB3/EvoTorch/NT train/save/load/parity/golden/restore 的完整记录校验；不会假装自行训练。
- `rollback_plan(...)`：输出固定旧 lock、adapter、artifact、复现旧报告哈希的计划；实际切换由用户执行。
- `audit_files` / `scan_text`：扫描疑似密钥且报告不回显密钥内容；不代替专用秘密检测工具。
- `ReleaseManifestBuilder(reviewer_approved, gates, trusted_producers).build(...)`：只输出待 Chief Reviewer 总装的 source/wheel/lock/SBOM/NOTICE/docs/cards 清单与哈希，不创建最终整包或 git tag。
- `evidence_bundle_index(reports,reviewer_approved)`：只建立 Q6–Q9 研究证据摘要索引，不把报告工件放进 AI-06 交付包。

### 5.1 最低门禁

Q0 Runtime → Q1 Data → Q2 Engine → Q3 Env Contract → Q4 Algorithms → Q5 Hybrid → Q6 Research Validity；Q7 Compute 和 Q8 Artifact、Q9 Upgrade 依其冻结依赖关系参与研究发布，Q10 Paper Ready 独立。CI 不能将 `FAILED`/staging 标为 `COMPLETE`。上游的完整 golden/集成证据与 reviewer 签核未经核验，一律阻断发布结论。

## 10. v0.4.1 后续功能与修正摘要（仍基于设计 v0.4.0）

### 10.1 生产接口增补

- `rles_compute_runtime.ComputeAllocation`：组合资源配额与 GPU 硬排他锁，阻止仅申请单侧配额而发生资源双重使用；锁冲突回滚新申请，不会自动破解陈旧 GPU 锁。
- `rles_compute_runtime.validate_benchmark_report(report)`：重算真实 probe 的重复样本摘要并校验预算和冻结指纹；`DeviceResolver.resolve(..., benchmark_report=report)` 的 `auto` 分支强制核实完整报告与 approved 决策摘要一致，不允许以单个决策字段绕过。
- `rles_research.ResearchLedger.evidence_summary(protocol_id)`：读取并哈希原始验证/HPO/ES/Test 查询清单及预算，明确**原始查询数不等于 DSR 有效独立试验数**；统计独立性仍须 ICR-L6-008 审批。
- `rles_research.candidate_set_sha256(candidate_ids)`：预冻结候选集合（含次序），`pbo_cscv(...,candidate_ids=...,candidate_set_hash=...)` 强制核验，否则拒绝统计计算。
- `rles_research.plan_stress_protocol(protocol_id,frozen_fingerprints)`：生成 20 种固定 ID 的研究压力/模拟器利用探测场景请求，包括延迟×2/×5、滑点、费率/资金费、行情缺失、价格冲击、未来数据扰动和 terminal 边界。产物是不可变的**请求协议**，不包含行情变换实现，也不等于已经完成压力回放。涉及缺失的数值极值/冲击参数必须由 L2/L3 及正式研究配方冻结，L6 不猜测。
- `l6_ci_release.verify_gate_reports`、`load_gate_reports` 及 `python -m l6_ci_release.attestation --reports <path> --trusted-producers <registry.json>`：复核 Q0–Q9 报告、哈希、检查项完整性、逐项证据及依赖拓扑；可信生产者清单由用户总集成提供，不包含签名或密钥。

### 10.2 不变量加固

1. ResourceQuota 仅在所有子进程被确认退出后释放；无法杀死的子进程必须保留租约等待人工排查。Pool 并发调用直接拒绝，拒绝跨 run/model/schema 的消息串线。
2. RL 已使用的 episode ID 不允许重新 reset/step；同一 VecEnv barrier 不能混入多个 run_attempt 或不同 dtype/shape。ES 候选遵循同一 run/attempt/model/schema 归属。
3. Holdout 强制记录并核实 `pre_holdout_end_ns <= holdout_start_ns`，且同一数据库中相同数据集指纹只能开启一次；升级已有数据库时添加相应列（不会回写已打开 Holdout 的时间证据）。
4. ArtifactStore 验证 committed L1 manifest 字段和完整索引 Schema；缺失/篡改即失败。升级差异即使改变事件数量也保留 C 类可审计结果。
5. PBO 候选身份、数量与切片长度强校验；DSR 的 `effective_trials` 必须为非布尔正整数并和 trial Sharpe 样本数量严格一致。
6. 研究发布清单构造函数现在强制再次核验全部 Q0–Q9 Gate 和证据文件；源码修订版未因此自动拥有任何实际 Gate PASS。

### 10.3 兼容性 / 迁移说明

- 本线内部公开接口有**显式安全收紧**：`open_holdout()` 新增必填 `holdout_start_ns`；`pbo_cscv()` 新增必填 `candidate_ids`；`DeviceResolver.resolve('auto',...)` 需 `benchmark_report`；`ReleaseManifestBuilder()` 新增 `trusted_producers`；`GateRunner` 每项固定检查都必须有相应 ID 的证据。现有集成消费方应提交 ICR / 做版本化对接，不能以默许 default 恢复旧行为。
- `ResearchLedger` 的 SQLite 表执行可回滚的增列迁移；原有研究协议的旧 state 不能被当作已具备新时序证据，需补齐前置证明才允许后续开启 Holdout。
- 所有 `0.4.1` wheel 版本标识为 **AI-06 源码修订版**；工程总体设计基线依旧是 **v0.4.0**，不修改 L1–L5 所有者的 DTO、工具或工程版本。
- 扩展 ICR-L6-004（L3 真实 READY/Worker CPU session/VecEnv episode）、ICR-L6-007（逐检查项证据、可信 producer registry 与签核机制）、ICR-L6-008（PBO 候选冻结、DSR 独立 trial 数/压力协议审核）；均等待用户总审查。

### 10.4 待总集成限制

所有历史约束继续有效。尤其：以上压力场景**未真实执行**，没有申请或宣称 Q6/Q7/Q8/Q9 通过；GPU 真实压测、真实 Nautilus 订单/账户语义、SB3/EvoTorch cp314 兼容、外部签核和跨数据库 Holdout 全局唯一性仍须用户独立验证。Gate 内容哈希和本地 producer allowlist **不是数字签名或不可否认性证明**。当前 SHA256/SQLite 实现默认本地文件系统可信。
